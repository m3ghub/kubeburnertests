                TEST 04: CLUSTER DENSITY V2 — THE MEGA CITY TEST                
================================================================================



  NOTE: Difficulty: ⭐⭐ Intermediate  


  NOTE: Time to run: ~20 minutes  


  NOTE: What it does: An enhanced version of Cluster Density that creates richer application stacks including NetworkPolicies and multiple container workloads — closer to what real enterprise clusters run


--------------------------------------------------------------------------------


--------------------------------------------------------------------------------
  WHAT IS THIS TEST? 🏗️
--------------------------------------------------------------------------------


Think of Cluster Density (Test 03) as building a small town.
Cluster Density v2 builds a mega city — same idea, but with:
  * More objects per namespace
  * NetworkPolicy rules (like security fences between neighbourhoods)
  * Multiple workload types per iteration
  * Higher pressure on the cluster's control plane

If your cluster can handle this test well, it is ready for real enterprise
workloads.

--------------------------------------------------------------------------------


--------------------------------------------------------------------------------
  HOW V2 DIFFERS FROM V1
--------------------------------------------------------------------------------



  +-----------------------+-------------------------------------------+--------------------------------------------------+
  | Feature               | Cluster Density (v1)                      | Cluster Density v2                               |
  +-----------------------+-------------------------------------------+--------------------------------------------------+
  | Objects per namespace | Deployment + Service + ConfigMap + Secret | All of v1 plus NetworkPolicy + extra Deployments |
  | Workloads             | 1 Deployment                              | 3+ Deployments with different sizes              |
  | Network pressure      | Minimal                                   | Medium (NetworkPolicies are enforced by CNI)     |
  | Control plane load    | Medium                                    | High                                             |
  | Realistic?            | Yes                                       | More realistic                                   |
  +-----------------------+-------------------------------------------+--------------------------------------------------+


--------------------------------------------------------------------------------


--------------------------------------------------------------------------------
  HOW IT WORKS
--------------------------------------------------------------------------------



    Each namespace (iteration) gets:
    
      Namespace: burner-cdv2-0
      ┌──────────────────────────────────────────────────────────────────┐
      │  Deployment-A (1 replica)  ──► Pod 🟢                           │
      │  Deployment-B (1 replica)  ──► Pod 🟢   (second workload)       │
      │  Service-A                 ──► routes to Deployment-A           │
      │  Service-B                 ──► routes to Deployment-B           │
      │  ConfigMap (x2)            ──► app configuration                │
      │  Secret                    ──► credentials                      │
      │  NetworkPolicy             ──► only allow traffic from app label│
      └──────────────────────────────────────────────────────────────────┘
    
      × N iterations = N fully isolated neighbourhoods with security rules

--------------------------------------------------------------------------------
  STEP-BY-STEP GUIDE
--------------------------------------------------------------------------------



Step 1 — Create the namespace
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~



  NOTE: Do this first — every other step depends on it.



    oc new-project burner-cdv2


You should see:

    Now using project "burner-cdv2" on server "https://api.<your-cluster>:6443"



  NOTE: OpenShift only: Never use kube- at the start of the name — it is reserved by the system and will be rejected.



Step 2 — Set up RBAC
~~~~~~~~~~~~~~~~~~~~


Every test needs a ServiceAccount, ClusterRole, and ClusterRoleBinding. Run all
three commands — they are safe to re-run if any already exist.

2a — Create the ServiceAccount in this namespace:


    oc create serviceaccount kube-burner -n burner-cdv2 \
      --dry-run=client -o yaml | oc apply -f -


2b — Apply the ClusterRole and ClusterRoleBinding (once per cluster):


  NOTE: These are applied inline below — no local file needed. Safe to re-run at any time.



    oc apply -f - <<'EOF'
    apiVersion: rbac.authorization.k8s.io/v1
    kind: ClusterRole
    metadata:
      name: kube-burner
    rules:
      - apiGroups: [""]
        resources: [namespaces, pods, services, endpoints, configmaps, secrets, nodes, events, replicationcontrollers, serviceaccounts]
        verbs: [get, list, watch, create, delete, update, patch]
      - apiGroups: [apps]
        resources: [deployments, replicasets, statefulsets, daemonsets]
        verbs: [get, list, watch, create, delete, update, patch]
      - apiGroups: [batch]
        resources: [jobs]
        verbs: [get, list, watch, create, delete, update, patch]
      - apiGroups: [networking.k8s.io]
        resources: [networkpolicies, ingresses]
        verbs: [get, list, watch, create, delete, update, patch]
      - apiGroups: [kubevirt.io]
        resources: [virtualmachines, virtualmachineinstances]
        verbs: [get, list, watch, create, delete, update, patch]
    ---
    apiVersion: rbac.authorization.k8s.io/v1
    kind: ClusterRoleBinding
    metadata:
      name: kube-burner
    roleRef:
      apiGroup: rbac.authorization.k8s.io
      kind: ClusterRole
      name: kube-burner
    subjects:
      - kind: ServiceAccount
        name: kube-burner
        namespace: burner-cdv2
    EOF


2c — Add this namespace to the ClusterRoleBinding:


    oc patch clusterrolebinding kube-burner \
      --type=json \
      -p='[{"op":"add","path":"/subjects/-","value":{"kind":"ServiceAccount","name":"kube-burner","namespace":"burner-cdv2"}}]' 2>/dev/null || true



  NOTE: The || true at the end means this command will not fail if the namespace is already listed. It is safe to run every time.


Verify all three are in place before continuing:


    oc get serviceaccount kube-burner -n burner-cdv2
    oc get clusterrole kube-burner
    oc get clusterrolebinding kube-burner -o jsonpath='{.subjects[*].namespace}'


The last command should include burner-cdv2 in the output.


Step 3 — Create config files
~~~~~~~~~~~~~~~~~~~~~~~~~~~~


Create cdv2-config.yml:


    cat > /tmp/cdv2-config.yml << 'EOF'
    global:
      gc: true
      measurements:
        - name: podLatency
    
    jobs:
      - name: cluster-density-v2
        namespace: burner-cdv2
        jobType: create
        jobIterations: 5
        namespacedIterations: true
        qps: 20
        burst: 20
        objects:
          - objectTemplate: deployment-a.yml
            replicas: 1
          - objectTemplate: deployment-b.yml
            replicas: 1
          - objectTemplate: service-a.yml
            replicas: 1
          - objectTemplate: service-b.yml
            replicas: 1
          - objectTemplate: configmap.yml
            replicas: 2
          - objectTemplate: secret.yml
            replicas: 1
          - objectTemplate: netpol.yml
            replicas: 1
        waitWhenFinished: true
        podWait: true
        maxWaitTimeout: 15m
    EOF


Create deployment-a.yml:


    cat > /tmp/deployment-a.yml << 'EOF'
    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: burner-app-a-{{.Iteration}}
      labels:
        app: burner-a-{{.Iteration}}
        tier: frontend
    spec:
      replicas: 1
      selector:
        matchLabels:
          app: burner-a-{{.Iteration}}
      template:
        metadata:
          labels:
            app: burner-a-{{.Iteration}}
            tier: frontend
        spec:
          containers:
            - name: frontend
              image: registry.k8s.io/pause:3.9
              resources:
                requests:
                  cpu: 1m
                  memory: 10Mi
    EOF


Create deployment-b.yml:


    cat > /tmp/deployment-b.yml << 'EOF'
    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: burner-app-b-{{.Iteration}}
      labels:
        app: burner-b-{{.Iteration}}
        tier: backend
    spec:
      replicas: 1
      selector:
        matchLabels:
          app: burner-b-{{.Iteration}}
      template:
        metadata:
          labels:
            app: burner-b-{{.Iteration}}
            tier: backend
        spec:
          containers:
            - name: backend
              image: registry.k8s.io/pause:3.9
              resources:
                requests:
                  cpu: 1m
                  memory: 10Mi
    EOF


Create service-a.yml:


    cat > /tmp/service-a.yml << 'EOF'
    apiVersion: v1
    kind: Service
    metadata:
      name: burner-svc-a-{{.Iteration}}
    spec:
      selector:
        app: burner-a-{{.Iteration}}
      ports:
        - port: 80
    EOF


Create service-b.yml:


    cat > /tmp/service-b.yml << 'EOF'
    apiVersion: v1
    kind: Service
    metadata:
      name: burner-svc-b-{{.Iteration}}
    spec:
      selector:
        app: burner-b-{{.Iteration}}
      ports:
        - port: 8080
    EOF


Create configmap.yml:


    cat > /tmp/configmap.yml << 'EOF'
    apiVersion: v1
    kind: ConfigMap
    metadata:
      name: burner-config-{{.Iteration}}-{{.Replica}}
    data:
      tier: "{{.Iteration}}"
      replica: "{{.Replica}}"
    EOF


Create secret.yml:


    cat > /tmp/secret.yml << 'EOF'
    apiVersion: v1
    kind: Secret
    metadata:
      name: burner-secret-{{.Iteration}}
    type: Opaque
    data:
      api-key: dGVzdC1rZXk=
    EOF


Create netpol.yml (the NetworkPolicy — the security fence):


    cat > /tmp/netpol.yml << 'EOF'
    apiVersion: networking.k8s.io/v1
    kind: NetworkPolicy
    metadata:
      name: burner-netpol-{{.Iteration}}
    spec:
      podSelector:
        matchLabels:
          app: burner-a-{{.Iteration}}
      policyTypes:
        - Ingress
      ingress:
        - from:
            - podSelector:
                matchLabels:
                  tier: frontend
    EOF


--------------------------------------------------------------------------------


Step 4 — Package into a ConfigMap
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~



    oc create configmap cdv2-config \
      --from-file=config.yml=/tmp/cdv2-config.yml \
      --from-file=deployment-a.yml=/tmp/deployment-a.yml \
      --from-file=deployment-b.yml=/tmp/deployment-b.yml \
      --from-file=service-a.yml=/tmp/service-a.yml \
      --from-file=service-b.yml=/tmp/service-b.yml \
      --from-file=configmap.yml=/tmp/configmap.yml \
      --from-file=secret.yml=/tmp/secret.yml \
      --from-file=netpol.yml=/tmp/netpol.yml \
      -n burner-cdv2


--------------------------------------------------------------------------------


Step 5 — Run the test!
~~~~~~~~~~~~~~~~~~~~~~



    cat <<'EOF' | oc apply -f -
    apiVersion: batch/v1
    kind: Job
    metadata:
      name: kb-cdv2
      namespace: burner-cdv2
    spec:
      backoffLimit: 0
      template:
        spec:
          serviceAccountName: kube-burner
          restartPolicy: Never
          initContainers:
            - name: copy-config
              image: quay.io/kube-burner/kube-burner:v2.6.1
              command: [sh, -c, "cp /config-src/* /config/"]
              volumeMounts:
                - {name: config-src, mountPath: /config-src}
                - {name: workdir,    mountPath: /config}
          containers:
            - name: kube-burner
              image: quay.io/kube-burner/kube-burner:v2.6.1
              workingDir: /config
              command: [kube-burner, init, -c, /config/config.yml, --uuid=cdv2-001]
              volumeMounts:
                - {name: workdir, mountPath: /config}
          volumes:
            - name: config-src
              configMap:
                name: cdv2-config
            - name: workdir
              emptyDir: {}
    EOF


--------------------------------------------------------------------------------


Step 6 — Watch objects appear
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~



    # Watch all resource types in the first namespace
    watch "oc get all,netpol,configmap,secret -n burner-cdv2-0"


--------------------------------------------------------------------------------


Step 7 — Read results
~~~~~~~~~~~~~~~~~~~~~



    oc logs -f job/kb-cdv2 -n burner-cdv2


Expected final output:


    time="..." level=info msg="cluster-density-v2: PodScheduled 99th: 700ms"
    time="..." level=info msg="cluster-density-v2: Ready        99th: 5500ms"
    time="..." level=info msg="Finished execution. UUID: cdv2-001"


--------------------------------------------------------------------------------


Step 8 — Clean up
~~~~~~~~~~~~~~~~~



    oc delete job kb-cdv2 -n burner-cdv2
    oc get namespaces | grep burner-cdv2 | awk '{print $1}' | xargs oc delete namespace

--------------------------------------------------------------------------------
  TROUBLESHOOTING
--------------------------------------------------------------------------------



  +----------------------------------------------------+------------------------------------------------------+
  | Problem                                            | Fix                                                  |
  +----------------------------------------------------+------------------------------------------------------+
  | networkpolicies is forbidden                       | Add networking.k8s.io to ClusterRole rules           |
  | NetworkPolicy creation slow                        | CNI is busy processing rules — reduce iterations     |
  | Pods from different deployments cannot communicate | This is expected! NetworkPolicy is working correctly |
  +----------------------------------------------------+------------------------------------------------------+
