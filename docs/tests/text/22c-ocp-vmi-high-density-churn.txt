================================================================================
   TEST 22C: OCP VMI HIGH-DENSITY MULTI-OS CHURN
================================================================================

  NOTE: Difficulty: ***** Expert -- Production Scale
  NOTE: Time to run: 60-120 minutes
  NOTE: What it does: Same 4-round progressive structure as 22B, but with
        10x the VM density -- 6 / 16 / 40 / 80 total VMs per round
  NOTE: Requires: OpenShift Virtualization 4.x, 6+ worker nodes, ~400 Gi storage
  NOTE: Run Test 22B first before running 22C

  22B vs 22C comparison:

  Round              22B VMs    22C VMs
  -----------------  ---------  ----------
  R01 (cirros)       6          6
  R02 (RHEL9)        4          16
  R03 (mixed)        3+3=6      20+20=40
  R04 (heavy mixed)  4+4=8      40+40=80

  RESOURCE DEMAND AT PEAK (Round 4):
    Per VM: 2 vCPU, 4 Gi RAM, 30 Gi storage
    Total:  160 vCPU, 320 Gi RAM, 2.4 Ti storage (spread across rounds)

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
  ROUND BREAKDOWN
--------------------------------------------------------------------------------

  Round  OS             VMs     vCPU  RAM    Churn  Approx time
  -----  -------------  ------  ----  -----  -----  -----------
  R01    cirros         6       1     512Mi  3      ~5 minutes
  R02    RHEL9          16      1     2Gi    3      ~25 minutes
  R03    RHEL9+Fedora   20+20   1     2Gi    3      ~40 minutes
  R04    RHEL9+Fedora   40+40   2     4Gi    2      ~50 minutes

--------------------------------------------------------------------------------
  WHAT IT MEASURES
--------------------------------------------------------------------------------

  VMIRunning P99      -- Boot latency at full fleet size
  VMReady P99         -- Cloud-init readiness at scale
  virt-controller RSS -- Memory footprint, watch for drift between rounds
  Delete duration     -- Time to remove 20 or 40 VMs at once
  Scheduler latency   -- Pod placement gap at high density
  CDI controller load -- NEW in 22C: visible at 40-80 concurrent PVC clones
  Stuck VM count      -- Must always be zero

--------------------------------------------------------------------------------
  BROWSER TABS TO OPEN
--------------------------------------------------------------------------------

  Tab 1: Console (terminal) -- Streaming kube-burner logs
  Tab 2: Virtualization > VirtualMachines -- Count reaching 16, 40, 80
  Tab 3: Observe > Metrics -- process_resident_memory_bytes{pod=~"virt-controller.*"}
  Tab 4: Observe > Metrics -- kubevirt_vmi_phase_count{phase="Running"}
  Tab 5: Observe > Metrics -- rate(process_cpu_seconds_total{pod=~"virt-handler.*"}[2m])*1000
  NOTE: Add Tab 5 CDI query -- not needed in 22B but visible at this scale

--------------------------------------------------------------------------------
  STEP 9 -- LAUNCH THE JOB
--------------------------------------------------------------------------------

  UUID="test22c-$(date +%s)"
  echo "UUID: $UUID"

  cat << JOBYAML | oc apply -f -
  apiVersion: batch/v1
  kind: Job
  metadata:
    name: kb-test22c-churn
    namespace: burner-test22c
  spec:
    backoffLimit: 0
    template:
      spec:
        serviceAccountName: kube-burner
        restartPolicy: Never
        initContainers:
          - name: copy-config
            image: quay.io/kube-burner/kube-burner:v2.6.1
            command: [sh, -c, "cp /config-src/* /config/"]
            volumeMounts:
              - {name: config-src, mountPath: /config-src}
              - {name: workdir,    mountPath: /config}
        containers:
          - name: kube-burner
            image: quay.io/kube-burner/kube-burner:v2.6.1
            workingDir: /config
            command: [kube-burner, init, -c, /config/config.yml, --uuid=${UUID}]
            volumeMounts:
              - {name: workdir, mountPath: /config}
        volumes:
          - name: config-src
            configMap:
              name: test22c-churn-config
          - name: workdir
            emptyDir: {}
  JOBYAML

Expected: job.batch/kb-test22c-churn created

--------------------------------------------------------------------------------
  STEP 11 -- WHAT TO SAY AT EACH PHASE
--------------------------------------------------------------------------------

During R01:
  "Same control-plane warm-up as 22B. Establishes the baseline."

During R02 (16 RHEL9):
  "Now we're at 16 real RHEL9 VMs -- 480 Gi of clone operations running in
   parallel. Watch Tab 2 as they all try to reach Running at the same time."

During R03 (40 mixed):
  "Two operating systems, 40 VMs total. Watch the CDI query in Tab 5 -- at
   this scale the clone controller becomes visible in the metrics. That is
   something you only see at real production density."

During R04 (80 VMs):
  "Full wall test -- 80 VMs, 160 vCPU, 320 Gi RAM. When churn starts, 40 VMs
   disappear and 40 new ones clone and boot. Watch virt-controller RSS in Tab 3.
   If it returns to near-baseline after R04, this cluster is production-ready."

--------------------------------------------------------------------------------
  STEP 12 -- WHAT GOOD LOOKS LIKE
--------------------------------------------------------------------------------

  Metric                     Healthy         Investigate
  -------------------------  --------------  ------------------
  R01 VMIRunning P99         < 30s           > 60s
  R02 VMIRunning P99         < 90s           > 5 minutes
  R03 VMIRunning P99         < 120s          > 8 minutes
  R04 VMIRunning P99         < 180s          > 12 minutes
  virt-controller RSS peak   < 400 MiB       > 800 MiB
  RSS after test             Returns ~base   Keeps climbing
  Stuck VMs                  0               Any
  Final VM count             0               Any remaining

  NOTE: Thresholds are higher than 22B because at 16-80 VMs, CDI clone queue
  depth and scheduler pack time both increase. Graceful scaling is the pass
  criteria, not matching the 22B absolute numbers.
