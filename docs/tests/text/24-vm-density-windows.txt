================================================================================
TEST 24: Windows Server VM Fleet Density — VMware Migration Demo
================================================================================
Difficulty:  Advanced (4 stars)
Time:        30-60 minutes
What it does: Creates N Windows Server 2022 VMs simultaneously — the most
             compelling VMware migration demo you can run
VM Image:    win2k22 DataVolume from openshift-virtualization-os-images
Requires:    OpenShift Virtualization, multi-node cluster, Windows golden image
================================================================================

WHAT IS THIS TEST?
------------------
When a customer is evaluating whether to move their VMware estate to OpenShift,
the most common objection is: "But can it run our Windows workloads?"

This test answers that with live proof: N Windows Server 2022 VMs booting
simultaneously on OpenShift Virtualization.

Windows takes 3-8 minutes to boot. That is not a problem — it is realistic.
Showing 10 Windows VMs come online over 5 minutes is more powerful than any
slide.

PRE-FLIGHT — VERIFY WINDOWS IMAGE
-----------------------------------
  oc get datavolume win2k22 -n openshift-virtualization-os-images

Must show PHASE: Succeeded. If not — contact your cluster administrator to
import the Windows Server 2022 golden image before running this test.

BEFORE YOU START — OPEN THESE TABS
-----------------------------------
Tab 1: Console web terminal
Tab 2: Virtualization → VirtualMachines
       (Windows VMs: Provisioning → Starting → Running)
Tab 3: Observe → Metrics (query: kubevirt_vmi_phase_count{phase="Running"})
Tab 4: Observe → Dashboards → KubeVirt / Infrastructure Resources / Top Consumers

STEP 1 — VERIFY PRE-FLIGHT
----------------------------
  oc whoami
  oc get hyperconverged -A
  oc get datavolume win2k22 -n openshift-virtualization-os-images

STEP 2 — SET PARAMETERS
-------------------------
  VM_COUNT=4
  UUID="windows-fleet-$(date +%s)"

STEP 3 — CREATE PROJECT AND RBAC
----------------------------------
  oc new-project burner-windows-fleet
  oc create serviceaccount kube-burner -n burner-windows-fleet

  oc apply -f - <<'EOF'
  apiVersion: rbac.authorization.k8s.io/v1
  kind: ClusterRole
  metadata:
    name: kube-burner
  rules:
    - apiGroups: [""]
      resources: [namespaces, pods, services, configmaps, secrets, nodes,
                  events, serviceaccounts, persistentvolumeclaims]
      verbs: [get, list, watch, create, delete, update, patch]
    - apiGroups: [kubevirt.io]
      resources: [virtualmachines, virtualmachineinstances]
      verbs: [get, list, watch, create, delete, update, patch]
    - apiGroups: [cdi.kubevirt.io]
      resources: [datavolumes]
      verbs: [get, list, watch, create, delete, update, patch]
    - apiGroups: [batch]
      resources: [jobs]
      verbs: [get, list, watch, create, delete, update, patch]
  ---
  apiVersion: rbac.authorization.k8s.io/v1
  kind: ClusterRoleBinding
  metadata:
    name: kube-burner
  roleRef:
    apiGroup: rbac.authorization.k8s.io
    kind: ClusterRole
    name: kube-burner
  subjects:
    - kind: ServiceAccount
      name: kube-burner
      namespace: burner-windows-fleet
  EOF

STEP 4 — WRITE CONFIG FILE
----------------------------
  cat > /tmp/windows-fleet-config.yml << EOF
  global:
    gc: false
    measurements:
      - name: vmiLatency
  jobs:
    - name: create-windows-vms
      namespace: burner-windows-fleet
      jobType: create
      jobIterations: 1
      namespacedIterations: false
      podWait: false
      waitWhenFinished: true
      maxWaitTimeout: 60m
      objects:
        - objectTemplate: /config/windows-vm-template.yml
          replicas: ${VM_COUNT}
    - name: delete-windows-vms
      namespace: burner-windows-fleet
      jobType: delete
      waitForDeletion: true
      objects:
        - apiVersion: kubevirt.io/v1
          kind: VirtualMachine
          labelSelector: {kube-burner-job: create-windows-vms}
  EOF

STEP 5 — WRITE WINDOWS VM TEMPLATE
-------------------------------------
  cat > /tmp/windows-vm-template.yml << 'EOF'
  apiVersion: kubevirt.io/v1
  kind: VirtualMachine
  metadata:
    name: win-vm-{{.Iteration}}-{{.Replica}}
    labels:
      app: windows-fleet
      os: windows2022
      kube-burner-job: create-windows-vms
  spec:
    running: true
    dataVolumeTemplates:
      - metadata:
          name: win-disk-{{.Iteration}}-{{.Replica}}
        spec:
          pvc:
            accessModes:
              - ReadWriteOnce
            resources:
              requests:
                storage: 50Gi
            storageClassName: ""
          source:
            pvc:
              namespace: openshift-virtualization-os-images
              name: win2k22
    template:
      metadata:
        labels:
          app: windows-fleet
          os: windows2022
      spec:
        domain:
          cpu:
            cores: 2
          resources:
            requests:
              memory: 4Gi
          features:
            acpi: {}
            apic: {}
            hyperv:
              relaxed: {}
              spinlocks:
                spinlocks: 8191
              vapic: {}
          clock:
            utc: {}
            timer:
              hpet:
                present: false
              pit:
                tickPolicy: delay
              rtc:
                tickPolicy: catchup
              hyperv: {}
          devices:
            disks:
              - name: rootdisk
                disk:
                  bus: sata
            interfaces:
              - name: default
                masquerade: {}
        networks:
          - name: default
            pod: {}
        volumes:
          - name: rootdisk
            dataVolume:
              name: win-disk-{{.Iteration}}-{{.Replica}}
  EOF

STEP 6 — CREATE CONFIGMAP
---------------------------
  oc create configmap windows-fleet-config \
    --from-file=config.yml=/tmp/windows-fleet-config.yml \
    --from-file=windows-vm-template.yml=/tmp/windows-vm-template.yml \
    -n burner-windows-fleet

STEP 7 — LAUNCH JOB AND STREAM LOGS
--------------------------------------
  (Apply Job YAML — see markdown guide for full job spec)

  oc get pod -n burner-windows-fleet -w
  oc logs -f job/kb-windows-fleet -n burner-windows-fleet

THE CUSTOMER DEMO — WHAT TO SAY
---------------------------------
Phase 1 - DataVolume cloning (1-3 min):
  "OpenShift is cloning the Windows golden image for each VM.
   Like deploying from a template in VMware."

Phase 2 - QEMU/BIOS startup (1-2 min):
  "Windows is booting. BIOS POST, kernel loading, services starting.
   Same as any Windows Server coming online."

Phase 3 - Windows Running:
  "Windows Server 2022, running on OpenShift. Not on VMware.
   Click any VM to open the VNC console and see the Windows desktop."

EXPECTED RESULTS
-----------------
  INFO vmiLatency:
  INFO   P50:  245s
  INFO   P95:  312s
  INFO   P99:  380s   <- Windows boots slowly — expected and honest

STEP 8 — CLEAN UP
-----------------
  oc delete job kb-windows-fleet -n burner-windows-fleet 2>/dev/null || true
  oc delete vm -A -l app=windows-fleet 2>/dev/null || true
  sleep 30
  oc delete project burner-windows-fleet
  oc delete clusterrole kube-burner 2>/dev/null || true
  oc delete clusterrolebinding kube-burner 2>/dev/null || true

TROUBLESHOOTING
---------------
  win2k22 DataVolume not found
    -> Windows golden image not imported — contact cluster admin

  VMs stuck in Provisioning > 10 min
    -> CDI still cloning — check: oc get datavolume -n burner-windows-fleet

  cannot create resource "datavolumes"
    -> Add cdi.kubevirt.io to ClusterRole (Step 3)

  Storage class not found
    -> Set storageClassName in template to your cluster's default
