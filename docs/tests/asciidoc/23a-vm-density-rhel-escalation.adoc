= Test 23a — RHEL VM Density Escalation (Set It and Forget It)

_Category:_ OpenShift Virtualization — RHEL 9 VM Density  
_Namespace:_ `burner-rhel-density-escalation`  
_Escalation:_ 5 → 10 → 20 → 40 → 80 VMs  
_Duration:_ ~60–120 min (DataVolume cloning is slower than containerDisk)  
_Difficulty:_ ⭐⭐⭐⭐ Expert

== What this test does

Automatically runs 5 escalating rounds using RHEL 9 golden images from `openshift-virtualization-os-images`. Each round clones the `rhel9` DataSource PVC for every VM, waits for all VMs to reach Running state, then deletes the VMs and their DataVolumes before the next round.

____
_Time warning:_ Each RHEL VM requires a PVC clone (~30Gi each). At Round 5 (80 VMs) that is 80 concurrent PVC clones. Allow 90 min per round on busy storage.
____

| Round | VMs | Storage cloned | Max Wait |
|-------|-----|----------------|----------|
| 1 | 5 | ~150 Gi | 90 min |
| 2 | 10 | ~300 Gi | 90 min |
| 3 | 20 | ~600 Gi | 90 min |
| 4 | 40 | ~1.2 Ti | 90 min |
| 5 | 80 | ~2.4 Ti | 90 min |

'''

== Prerequisites

* OpenShift cluster with OpenShift Virtualization installed
* `oc` CLI logged in with cluster-admin
* Verify the RHEL 9 DataSource is available:

[source]
----
oc get datasource rhel9 -n openshift-virtualization-os-images
----

Expected:

[source]
----
NAME    AGE   PHASE   READY   MESSAGE
rhel9   73m   Ready   True    DataSource is ready to be consumed
----

* If only `rhel8` is available, replace `rhel9` with `rhel8` in the VM template.
* Verify sufficient storage: `oc get storageclass` — need a CSI-backed class that supports `ReadWriteMany` or PVC cloning.

'''

== Security — DISA STIG-hardened job manifest

If your cluster enforces DISA STIG hardening (e.g. the `restricted-v2` SCC, a compliance-operator profile, or an admission policy requiring non-root containers and no Linux capabilities), the Step 4 job manifest above may fail admission. Use this hardened variant instead — it adds a pod-level `securityContext` (non-root, `RuntimeDefault` seccomp profile) plus container-level `securityContext` (no privilege escalation, all capabilities dropped) on both the init container and the `kube-burner` container:

[source,bash]
----
cat <<'EOF' | oc apply -f -
apiVersion: batch/v1
kind: Job
metadata:
  name: kb-rhel-escalation
  namespace: burner-rhel-density-escalation
spec:
  template:
    spec:
      serviceAccountName: kube-burner
      securityContext:
        runAsNonRoot: true
        seccompProfile:
          type: RuntimeDefault
      initContainers:
        - name: copy-config
          image: registry.redhat.io/ubi9/ubi-minimal:latest
          command: ["sh","-c","cp /configmap/* /config/"]
          securityContext:
            allowPrivilegeEscalation: false
            capabilities:
              drop: ["ALL"]
          volumeMounts:
            - name: configmap-vol
              mountPath: /configmap
            - name: config-vol
              mountPath: /config
      containers:
        - name: kube-burner
          image: quay.io/kube-burner/kube-burner:v2.7.3
          command:
            - kube-burner
            - init
            - -c
            - /config/config.yml
            - --uuid
            - rhel-escalation-001
          securityContext:
            allowPrivilegeEscalation: false
            capabilities:
              drop: ["ALL"]
          volumeMounts:
            - name: config-vol
              mountPath: /config
      volumes:
        - name: configmap-vol
          configMap:
            name: rhel-escalation-config
        - name: config-vol
          emptyDir: {}
      restartPolicy: Never
EOF
----

____
_Note:_ The init container image was swapped from `busybox` to `registry.redhat.io/ubi9/ubi-minimal:latest` since STIG-locked registries typically only permit signed Red Hat UBI images.
____

== Force-stop a stuck or failing round

[source]
----
= Delete the job
oc delete job kb-rhel-escalation -n burner-rhel-density-escalation

= Delete VMs (DataVolumes will be garbage-collected automatically)
oc delete vm -l app=rhel-density-escalation -n burner-rhel-density-escalation --wait=false

= If DVs linger, delete them explicitly
oc delete dv --all -n burner-rhel-density-escalation --wait=false

= Watch cleanup progress
oc get vm,dv -n burner-rhel-density-escalation -w
----

'''

== Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| DataVolume stuck `Cloning` | Storage class doesn't support cloning | Use a CSI class; check `oc get storageclass` |
| `rhel9` DataSource not found | OS image not imported | Run `oc get datasource -n openshift-virtualization-os-images` |
| VMs stuck `Pending` | Not enough memory (2Gi each) | Reduce `replicas` in round config |
| Round times out | PVC cloning slow under load | Increase `maxWaitTimeout` to `120m` |
