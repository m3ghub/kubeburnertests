Test 23: RHEL 9 VM Fleet Density — Enterprise Linux at Scale

Difficulty: ⭐⭐⭐⭐ Advanced
Time to run: ~20–40 minutes
What it does: Creates N RHEL 9 virtual machines simultaneously and measures KubeVirt boot latency for enterprise Linux workloads
Requires: OpenShift Virtualization 4.x, multi-node cluster, RHEL 9 golden image available
VM Image: RHEL 9 golden image from openshift-virtualization-os-images (pre-loaded on most OCP Virt clusters)

What is this test? 🐧

CirrOS boots in 5 seconds. Your customers are not running CirrOS. They are running RHEL — the same operating system that runs their databases, their middleware, their compliance-critical workloads.

This test uses the RHEL 9 golden image that OpenShift Virtualization pre-loads on the cluster and asks: how many enterprise Linux VMs can OpenShift Virtualization boot at the same time?

When you show this to a customer migrating from VMware: "Every VM you see booting is RHEL 9 — the same OS running your production workloads right now. We're starting them all simultaneously. This is what your migration day looks like."

What makes RHEL different from CirrOS:

  • Boots the full Linux kernel + systemd + cloud-init (~90 seconds vs 5 seconds)
  • Uses cloud-init for user injection (realistic provisioning workflow)
  • Needs 2 GiB RAM per VM (vs 512 MiB for CirrOS)
  • Represents actual customer database, app server, and middleware workloads

    Step 7 — Write the RHEL 9 VM template

    Choose the template that matches the method you confirmed in Check 4 of pre-flight.

    Method A — OCP golden image (recommended)

    Uses the RHEL 9 DataSource already on the cluster. No external registry needed:

    cat > /tmp/rhel-vm-template.yml << 'EOF'
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: rhel-vm-{{.Iteration}}-{{.Replica}}
  labels:
    app: rhel-fleet
    os: rhel9
    kube-burner-job: create-rhel-vms
spec:
  running: true
  dataVolumeTemplates:
    - metadata:
        name: rhel-disk-{{.Iteration}}-{{.Replica}}
      spec:
        sourceRef:
          kind: DataSource
          name: rhel9                                   # Change to rhel8 if needed
          namespace: openshift-virtualization-os-images
        storage:
          resources:
            requests:
              storage: 30Gi
  template:
    metadata:
      labels:
        app: rhel-fleet
        os: rhel9
    spec:
      domain:
        cpu:
          cores: 1
        resources:
          requests:
            memory: 2Gi
        devices:
          disks:
            - name: rootdisk
              disk:
                bus: virtio
            - name: cloudinitdisk
              disk:
                bus: virtio
          interfaces:
            - name: default
              masquerade: {}
      networks:
        - name: default
          pod: {}
      volumes:
        - name: rootdisk
          dataVolume:
            name: rhel-disk-{{.Iteration}}-{{.Replica}}
        - name: cloudinitdisk
          cloudInitNoCloud:
            userData: |
              #cloud-config
              hostname: rhel-vm-{{.Iteration}}-{{.Replica}}
              user: cloud-user
              password: redhat123
              chpasswd:
                expire: false
              ssh_pwauth: true
EOF

    Step 9 — Launch the Job

    cat << JOBYAML | oc apply -f -
apiVersion: batch/v1
kind: Job
metadata:
  name: kb-rhel-fleet
  namespace: burner-rhel-fleet
spec:
  backoffLimit: 0
  template:
    spec:
      serviceAccountName: kube-burner
      restartPolicy: Never
      initContainers:
        - name: copy-config
          image: quay.io/kube-burner/kube-burner:v2.7.3
          command: [sh, -c, "cp /config-src/* /config/"]
          volumeMounts:
            - {name: config-src, mountPath: /config-src}
            - {name: workdir,    mountPath: /config}
      containers:
        - name: kube-burner
          image: quay.io/kube-burner/kube-burner:v2.7.3
          workingDir: /config
          command: [kube-burner, init, -c, /config/config.yml, --uuid=${UUID}]
          volumeMounts:
            - {name: workdir, mountPath: /config}
      volumes:
        - name: config-src
          configMap:
            name: rhel-fleet-config
        - name: workdir
          emptyDir: {}
JOBYAML

    Step 10 — Watch the pod start, then stream logs

    Step 11 — Watch the RHEL boot sequence in the console

    Tab 2 (Virtualization → VirtualMachines): Watch VMs appear. They go through Provisioning (disk clone), then Starting (QEMU init), then Running (systemd ready).

    This is the moment to narrate to a customer: "Each one of those is a full RHEL 9 instance booting — kernel loading, systemd starting services, cloud-init running. This is what your actual server workloads look like running on OpenShift instead of bare metal or VMware."

    Tab 3 (Observe → Metrics):

    kubevirt_vmi_phase_count{phase="Running"}

    Watch the count climb from 0. It will be slower than CirrOS — that is expected and real.

    Tab 4 (Dashboards → KubeVirt Top Consumers): Watch memory consumption climbing as VMs allocate their 2 GiB per guest.
