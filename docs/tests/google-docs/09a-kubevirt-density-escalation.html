Test 09a — KubeVirt Density Escalation (Set It and Forget It)

Category: OpenShift Virtualization — CirrOS VM Density
Namespace: burner-escalation
Escalation: 5 → 15 → 30 → 60 → 100 VMs
Duration: ~20–40 min
Difficulty: ⭐⭐⭐ Advanced

What this test does

Automatically runs 5 back-to-back density rounds using lightweight CirrOS VMs. Each round creates VMs, waits for them all to reach Running state, then deletes them before proceeding to the next round. No manual intervention required.

RoundVMsMax Wait ---------------------- 1530 min 21530 min 33030 min 46030 min 510030 min

Prerequisites

  • OpenShift cluster with OpenShift Virtualization installed
  • oc CLI logged in with cluster-admin
  • Verify image pull works: oc debug node/ -- chroot /host crictl pull quay.io/kubevirt/cirros-registry-disk-demo:latest

    Step 4 — Launch the job

    cat <<'EOF' | oc apply -f -
apiVersion: batch/v1
kind: Job
metadata:
  name: kb-escalation
  namespace: burner-escalation
spec:
  template:
    spec:
      serviceAccountName: kube-burner
      initContainers:
        - name: copy-config
          image: busybox
          command: ["sh","-c","cp /configmap/* /config/"]
          volumeMounts:
            - name: configmap-vol
              mountPath: /configmap
            - name: config-vol
              mountPath: /config
      containers:
        - name: kube-burner
          image: quay.io/kube-burner/kube-burner:v2.7.3
          command:
            - kube-burner
            - init
            - -c
            - /config/config.yml
            - --uuid
            - cirros-escalation-001
          volumeMounts:
            - name: config-vol
              mountPath: /config
      volumes:
        - name: configmap-vol
          configMap:
            name: escalation-config
        - name: config-vol
          emptyDir: {}
      restartPolicy: Never
EOF

    Security — DISA STIG-hardened job manifest

    If your cluster enforces DISA STIG hardening (e.g. the restricted-v2 SCC, a compliance-operator profile, or an admission policy requiring non-root containers and no Linux capabilities), the job manifest above may fail admission. Use this hardened variant instead — it adds a pod-level securityContext (non-root, RuntimeDefault seccomp profile) plus container-level securityContext (no privilege escalation, all capabilities dropped) on every container in the Job.

    cat <<'EOF' | oc apply -f -
apiVersion: batch/v1
kind: Job
metadata:
  name: kb-escalation
  namespace: burner-escalation
spec:
  template:
    spec:
      serviceAccountName: kube-burner
      securityContext:
        runAsNonRoot: true
        seccompProfile:
          type: RuntimeDefault
      initContainers:
        - name: copy-config
          image: registry.redhat.io/ubi9/ubi-minimal:latest
          command: ["sh","-c","cp /configmap/* /config/"]
          securityContext:
            allowPrivilegeEscalation: false
            capabilities:
              drop: ["ALL"]
          volumeMounts:
            - name: configmap-vol
              mountPath: /configmap
            - name: config-vol
              mountPath: /config
      containers:
        - name: kube-burner
          image: quay.io/kube-burner/kube-burner:v2.7.3
          command:
            - kube-burner
            - init
            - -c
            - /config/config.yml
            - --uuid
            - cirros-escalation-001
          securityContext:
            allowPrivilegeEscalation: false
            capabilities:
              drop: ["ALL"]
          volumeMounts:
            - name: config-vol
              mountPath: /config
      volumes:
        - name: configmap-vol
          configMap:
            name: escalation-config
        - name: config-vol
          emptyDir: {}
      restartPolicy: Never
EOF
    Note: The init container image was swapped from busybox to registry.redhat.io/ubi9/ubi-minimal:latest since STIG-locked registries typically only permit signed Red Hat UBI images.

    Step 5 — Monitor

    Watch job pod
    
oc get pods -n burner-escalation -w


    Stream logs
    
oc logs -f job/kb-escalation -n burner-escalation


    Watch VMs during a round
    
watch -n5 'oc get vm -n burner-escalation | tail -20'

    Expected output per round:

    time="..." level=info msg="Triggering job: r01-create" ...
time="..." level=info msg="Job r01-create took 45s" ...
time="..." level=info msg="Triggering job: r01-delete" ...
time="..." level=info msg="Finished execution with UUID: cirros-escalation-001" ...

    Force-stop a stuck or failing round

    Delete the job
    
oc delete job kb-escalation -n burner-escalation


    Delete any remaining VMs
    
oc delete vm -l app=burner-escalation -n burner-escalation --wait=false


    Watch deletion progress
    
oc get vm -n burner-escalation -w

    Cleanup

    oc delete job kb-escalation -n burner-escalation 2>/dev/null || true
oc delete configmap escalation-config -n burner-escalation 2>/dev/null || true
oc delete vm -l app=burner-escalation -n burner-escalation --wait=false 2>/dev/null || true
oc delete project burner-escalation
oc delete clusterrole kube-burner-virt
oc delete clusterrolebinding kube-burner-virt-escalation
