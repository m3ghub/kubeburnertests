Test 16: VM Pause/Unpause Storm — Freezing and Thawing VMs at Scale

Difficulty: ⭐⭐⭐ Advanced
Time to run: ~15 minutes
What it does: Creates running VMs, then rapidly pauses and unpauses all of them — testing QEMU state snapshots, memory balloon driver, and virt-handler response time
Requires: OpenShift Virtualization (KubeVirt) installed


What is this test? ❄️▶️🖥️

Imagine hitting the pause button on 50 games simultaneously, then pressing play on all of them at once — while measuring how long each one takes to freeze and resume.

Pausing a VM does not shut it down. Instead, KubeVirt sends a signal to the QEMU process to:

  • Save CPU state (registers, instruction pointer, in-flight operations)
  • Freeze all I/O (writes queued but not executed)
  • Deflate the memory balloon (minimise RAM footprint)

Unpausing reverses all of this instantly — the VM resumes exactly where it left off.



How pause/unpause works

RUNNING VM                    PAUSED VM
──────────────                ─────────────────────────
CPU executing code            CPU state saved (frozen)
Memory in use: 512Mi          Memory balloon: minimised
I/O active                    I/O queued (frozen)
QEMU: running                 QEMU: paused (SIGSTOP)
VMI status: Running           VMI status: Paused
                              ↕  (instant transition)


What does it measure?

MetricWhat it means
Pause latencyTime from pause command to VMI status = Paused
Unpause latencyTime from unpause command to VMI status = Running
virt-handler response timeHow fast per-node agents process commands
Concurrent pause throughputHow many VMs can be paused per second
State consistencyWhether all VMs resume correctly after unpause


Step-by-step guide

Step 1 — Create namespace and RBAC
oc new-project burner-pause

Apply RBAC — the ClusterRole must include virtualmachines/pause and virtualmachines/unpause in the subresources list:

  - apiGroups: [subresources.kubevirt.io]
    resources:
      - virtualmachines/start
      - virtualmachines/stop
      - virtualmachines/pause
      - virtualmachines/unpause
      - virtualmachines/restart
    verbs: [update]
Step 2 — Create config (vm-pause-config.yml)
global:
  gc: true
  measurements: []

jobs:
  - name: create-vms
    jobType: create
    namespace: burner-pause
    namespacedIterations: false
    jobIterations: 1
    qps: 5
    burst: 5
    waitWhenFinished: false
    objects:
      - objectTemplate: vm-pause-template.yml
        replicas: 8
        wait: false
        inputVars:
          memory: 128Mi

  - name: start-vms
    jobType: kubevirt
    executionMode: parallel
    jobPause: 60s
    objects:
      - kubeVirtOp: start
        labelSelector: {kube-burner.io/job: create-vms}

  - name: pause-vms
    jobType: kubevirt
    executionMode: parallel      # Pause all at once
    jobPause: 15s
    objects:
      - kubeVirtOp: pause
        labelSelector: {kube-burner.io/job: create-vms}

  - name: unpause-vms
    jobType: kubevirt
    executionMode: parallel      # Unpause all at once
    jobPause: 30s
    objects:
      - kubeVirtOp: unpause
        labelSelector: {kube-burner.io/job: create-vms}

  - name: pause-vms-cycle2
    jobType: kubevirt
    executionMode: parallel
    jobPause: 10s
    objects:
      - kubeVirtOp: pause
        labelSelector: {kube-burner.io/job: create-vms}

  - name: unpause-vms-cycle2
    jobType: kubevirt
    executionMode: parallel
    jobPause: 20s
    objects:
      - kubeVirtOp: unpause
        labelSelector: {kube-burner.io/job: create-vms}

  - name: stop-vms
    jobType: kubevirt
    executionMode: parallel
    objects:
      - kubeVirtOp: stop
        labelSelector: {kube-burner.io/job: create-vms}
        inputVars:
          force: false
Step 3 — Watch the VMs freeze and thaw
# Watch VM status change: Running → Paused → Running
watch "oc get vmi -n burner-pause -o wide"

Expected status progression:

NAME              PHASE     NODE
pause-vm-1-1      Running   worker-1
pause-vm-1-2      Running   worker-1
# After pause-vms phase:
pause-vm-1-1      Paused    worker-1
# After unpause-vms phase:
pause-vm-1-1      Running   worker-1
Step 4 — Push harder

Increase to 20 VMs for stronger virt-handler pressure:

objects:
  - objectTemplate: vm-pause-template.yml
    replicas: 20

Signs the virt-handler is saturated:

  • Pause operations taking >30 seconds per VM
  • VMIs stuck in Pausing state
  • virt-handler pod CPU at 100% on worker nodes
Step 5 — Clean up
oc delete job kb-vm-pause -n burner-pause 2>/dev/null || true
oc delete project burner-pause
oc delete clusterrole kube-burner-virt
oc delete clusterrolebinding kube-burner-virt


Troubleshooting

ProblemFix
VMs stuck in PausingReduce replicas or use sequential execution mode
forbidden: virtualmachines/pauseAdd pause/unpause to ClusterRole subresources
Unpause fails after long pauseIf paused >10 minutes, restart the VM instead of unpausing
Second cycle slower than firstExpected — QEMU CPU cache reload after unpause is normal
