Test 22: OCP VMI Density + Churn — The Ultimate Soak Test

Difficulty: ⭐⭐⭐⭐⭐ Expert
Time to run: 30–60 minutes (configurable)
What it does: Brings up N VMs, then continuously deletes and recreates a percentage in cycles — the closest thing to a real production day on an OpenShift Virtualization cluster
Requires: OpenShift Virtualization 4.x, multi-node cluster

What is this test? 🔄🖥️

Imagine the VMI density test (Test 20) — but instead of turning it off after everything is running, you leave it on for 30–60 minutes and keep pulling virtual machines out and replacing them in a continuous cycle, like a conveyor belt that never stops.

This is the test that finds the problems no 5-minute benchmark ever catches.

Memory leaks. Stale objects piling up in etcd. virt-handler slowly grinding to a halt. virt-launcher pods that never finish terminating.

What to say: "This isn't a sprint — it's a marathon. We're running your VM workload continuously for 30 minutes, churning machines in and out the way your production automation would."

How it works — two phases

Phase 1 — Density
  └─► Creates N VMs with running: true
  └─► Waits for all to reach Running
  └─► Records vmiLatency P50/P95/P99

Phase 2 — Churn (repeats in cycles)
  └─► Delete job: removes a percentage of VMs
  └─► Create job: recreates the same number
  └─► Waits for all to reach Running again
  └─► Repeats for N cycles

Phase 3 — Final cleanup
  └─► Removes all remaining VMs

What it measures

MetricWhat it means
VMI boot time P50/P95/P99Baseline latency in the density phase
Churn cycle durationTime for one delete+recreate cycle
virt-controller memory (RSS)Should stay flat — growing RSS = memory leak
Stuck VM countVMs that never reach Running (should be 0)

Step-by-step guide

Step 1 — Verify OpenShift Virtualization
oc whoami
oc get hyperconverged -A
oc get nodes -l node-role.kubernetes.io/worker --no-headers | wc -l
The hyperconverged query must return a result. Minimum 2 worker nodes required.
Step 2 — Choose parameters
Cluster sizeTOTAL_VMSCHURN_VMSCHURN_CYCLES
2–3 workers623
4–6 workers1535
6+ workers3065
Step 3 — Create the project and RBAC
oc new-project burner-vmi-churn
oc create serviceaccount kube-burner -n burner-vmi-churn

Apply ClusterRole (must include kubevirt.io) and ClusterRoleBinding. Verify all three exist.

Step 4 — Set parameters
TOTAL_VMS=6
CHURN_VMS=2
CHURN_CYCLES=3
UUID="vmi-churn-$(date +%s)"
Step 5 — Write config and VM template, create ConfigMap

Write /tmp/vmi-churn-config.yml with density-phase + churn-delete-N + churn-create-N + final-delete jobs (using gc: false, namespacedIterations: false, vmiLatency).

Write /tmp/vmi-churn-template.yml with running: true and cirros disk.

Step 5b — Verify both files exist before continuing:
ls -lh /tmp/vmi-churn-config.yml \
        /tmp/vmi-churn-template.yml

Both must show non-zero sizes. If either is missing, re-run Step 5.

oc create configmap vmi-churn-config \
  --from-file=config.yml=/tmp/vmi-churn-config.yml \
  --from-file=vm-template.yml=/tmp/vmi-churn-template.yml \
  -n burner-vmi-churn
Step 6 — Launch the Job
cat << JOBYAML | oc apply -f -
# (Job YAML from full markdown guide — uses kube-burner:v2.6.1)
JOBYAML

oc get pod -n burner-vmi-churn -w
# Wait for Running, then:
oc logs -f job/kb-vmi-churn -n burner-vmi-churn
Step 7 — Watch the three key signals

Signal 1 — Tab 2 (Virtualization → VirtualMachines): Count climbs in density phase, dips and recovers in each churn cycle. Steady recovery is healthy.

Signal 2 — Tab 3 (Observe → Metrics):

process_resident_memory_bytes{pod=~"virt-controller.*"}

This line should be flat. Steady growth = memory leak.

Signal 3 — Tab 3, second query:

kubevirt_vmi_phase_count{phase="Running"}

Should dip and recover with each cycle. Doesn't recover = VMs getting stuck.

Set It and Forget It — Mixed Windows + RHEL Churn

5-round automated soak: each round creates a mixed fleet of Windows Server + RHEL VMs, churns them through full-rotation cycles (delete all Windows → recreate Windows → delete all RHEL → recreate RHEL), cleans up, then moves to the next heavier round.

Time warning: Full 5-round run can take 4–8 hours. Storage: each Windows VM clones a 60 Gi PVC — released after each round's final cleanup.
Step 1 — Create project and RBAC
oc new-project burner-mixed-churn
oc create serviceaccount kube-burner -n burner-mixed-churn

Apply ClusterRole kube-burner-virt (includes kubevirt.io + cdi.kubevirt.io) and ClusterRoleBinding kube-burner-virt-mixed-churn. See full markdown guide for YAML.

oc get serviceaccount kube-burner -n burner-mixed-churn
oc get clusterrolebinding kube-burner-virt-mixed-churn
Step 2 — Check golden images
oc get pvc -n openshift-virtualization-os-images | grep win2k22
oc get datasource rhel9 -n openshift-virtualization-os-images
oc adm top nodes

If win2k22 is not the PVC name, find yours: oc get pvc -n openshift-virtualization-os-images | grep -i win

Step 3 — Download config files
BASE="https://raw.githubusercontent.com/m3ghub/kubeburnertests/main/docs/tests/files/22-ocp-vmi-density-churn"
curl --fail -sL "${BASE}/mixed-churn-config.yml"   -o /tmp/mixed-churn-config.yml
curl --fail -sL "${BASE}/vm-template-windows.yml"  -o /tmp/vm-template-windows.yml
curl --fail -sL "${BASE}/vm-template-rhel.yml"     -o /tmp/vm-template-rhel.yml

Verify downloads (must print real YAML headers, not 404 HTML):

head -1 /tmp/mixed-churn-config.yml     # must print: global:
head -1 /tmp/vm-template-windows.yml    # must print: apiVersion: kubevirt.io/v1
head -1 /tmp/vm-template-rhel.yml       # must print: apiVersion: kubevirt.io/v1
If downloads fail, use Option B in the full markdown guide (manual paste, 3 blocks).
Step 3b — Verify all 3 files exist before continuing:
ls -lh /tmp/mixed-churn-config.yml \
        /tmp/vm-template-windows.yml \
        /tmp/vm-template-rhel.yml

All 3 must show non-zero sizes. If any is missing, re-run Step 3.

Step 4 — Create ConfigMap
UUID="mixed-churn-$(date +%s)"

oc create configmap mixed-churn-config \
  --from-file=config.yml=/tmp/mixed-churn-config.yml \
  --from-file=vm-template-windows.yml=/tmp/vm-template-windows.yml \
  --from-file=vm-template-rhel.yml=/tmp/vm-template-rhel.yml \
  -n burner-mixed-churn

oc get configmap mixed-churn-config -n burner-mixed-churn
Step 5 — Launch the Job

oc delete vm -l os=rhel9 -n burner-mixed-churn 2>/dev/null || true
