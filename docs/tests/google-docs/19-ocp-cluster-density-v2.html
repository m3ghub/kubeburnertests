Test 19: OCP Cluster Density v2 — Full-Stack Multi-Tenant Scale

Difficulty: ⭐⭐⭐⭐ Advanced
Time to run: ~20–30 minutes
What it does: Creates N namespaces simultaneously, each with a Deployment, Service, Route, ConfigMaps, Secrets, and NetworkPolicy — the most realistic production workload simulation available
Requires: Multi-node OpenShift cluster

⚡ Pre-flight required: Before running this test, verify kube-burner is pullable on your cluster and your environment is ready — see 00-preflight.md.

What is this test? 🏙️

Imagine spinning up a brand new city from scratch — but not just empty buildings. Every block has a working storefront (Deployment), a road name (Service), a postal address accessible from outside (Route), a security fence (NetworkPolicy), and a key box with secrets (ConfigMap + Secret).

Now do that for 500 blocks simultaneously.

Cluster Density v2 is the most realistic OpenShift workload test there is. It doesn't just measure whether the API server can take writes — it measures whether the whole stack can handle real enterprise tenants being provisioned at scale: routers, policy controllers, endpoint slices, and the etcd write storm that comes with all of it.

When you demo this to a customer: "This is what 500 namespaces of production workloads hitting your cluster at the same time looks like — and your cluster handled it in under 20 minutes."

What this test does

cluster-density-v2 is the closest approximation to a real production OpenShift workload.

Each iteration creates one namespace containing:

  • A Deployment (configurable replicas) with resource requests, liveness + readiness probes
  • A Service pointing to the Deployment
  • An OpenShift Route (tests the OpenShift router, not just Services)
  • ConfigMaps and Secrets mounted into the Deployment
  • A NetworkPolicy restricting ingress

    • This makes it significantly heavier than cluster-density (v1). Run this before major

    cluster upgrades, after adding worker nodes, or to establish a capacity baseline.

    • Step-by-step guide

    Step 1 — Open the web terminal

    Click the >_ icon in the top-right toolbar. Confirm connectivity:

    oc whoami
oc get nodes --no-headers | awk '{print $1, $2}'

    Step 2 — Choose your iteration count

    Cluster sizeStarterMediumHeavy 3-worker OCP50 namespaces100 namespaces200 namespaces 6+ workers200 namespaces500 namespaces1000 namespaces

    Step 3 — Create the project and RBAC

    oc new-project burner-cluster-density
oc create serviceaccount kube-burner -n burner-cluster-density

    oc apply -f - <<'EOF'
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: kube-burner
rules:
  - apiGroups: [""]
    resources: [namespaces, pods, services, endpoints, configmaps, secrets, nodes, events, replicationcontrollers, serviceaccounts]
    verbs: [get, list, watch, create, delete, update, patch]
  - apiGroups: [apps]
    resources: [deployments, replicasets, statefulsets, daemonsets]
    verbs: [get, list, watch, create, delete, update, patch]
  - apiGroups: [batch]
    resources: [jobs]
    verbs: [get, list, watch, create, delete, update, patch]
  - apiGroups: [networking.k8s.io]
    resources: [networkpolicies, ingresses]
    verbs: [get, list, watch, create, delete, update, patch]
  - apiGroups: [route.openshift.io]
    resources: [routes]
    verbs: [get, list, watch, create, delete, update, patch]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: kube-burner
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: kube-burner
subjects:
  - kind: ServiceAccount
    name: kube-burner
    namespace: burner-cluster-density
EOF

    Verify:

    oc get serviceaccount kube-burner -n burner-cluster-density
oc get clusterrole kube-burner
oc get clusterrolebinding kube-burner

    Step 4 — Switch to Tab 2

    Go to Home → Projects. Watch the project counter — it will climb as namespaces are created.

    Step 5 — Write the config files

    ITERATIONS=50
UUID="cluster-density-$(date +%s)"

cat > /tmp/cluster-density-config.yml << EOF
global:
  gc: false
  measurements:
    - name: podLatency

jobs:
  - name: create-namespaces
    jobType: create
    jobIterations: ${ITERATIONS}
    namespacedIterations: true
    namespace: cluster-density-v2
    podWait: true
    waitWhenFinished: true
    maxWaitTimeout: 20m
    objects:
      - objectTemplate: /config/deployment-template.yml
        replicas: 1
      - objectTemplate: /config/service-template.yml
        replicas: 1
      - objectTemplate: /config/route-template.yml
        replicas: 1
      - objectTemplate: /config/networkpolicy-template.yml
        replicas: 1
EOF

    Write the deployment template:

    cat > /tmp/deployment-template.yml << 'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: app-{{.Iteration}}
  labels:
    app: cluster-density
    kube-burner-job: create-namespaces
spec:
  replicas: 2
  selector:
    matchLabels:
      app: cluster-density
  template:
    metadata:
      labels:
        app: cluster-density
    spec:
      containers:
        - name: app
          image: gcr.io/google_containers/pause:3.1
          resources:
            requests:
              cpu: 10m
              memory: 10Mi
EOF

    Write the service template:

    cat > /tmp/service-template.yml << 'EOF'
apiVersion: v1
kind: Service
metadata:
  name: app-svc-{{.Iteration}}
  labels:
    kube-burner-job: create-namespaces
spec:
  selector:
    app: cluster-density
  ports:
    - port: 80
      targetPort: 8080
EOF

    Write the route template:

    cat > /tmp/route-template.yml << 'EOF'
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: app-route-{{.Iteration}}
  labels:
    kube-burner-job: create-namespaces
spec:
  to:
    kind: Service
    name: app-svc-{{.Iteration}}
  port:
    targetPort: 8080
EOF

    Write the network policy template:

    cat > /tmp/networkpolicy-template.yml << 'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-external-{{.Iteration}}
  labels:
    kube-burner-job: create-namespaces
spec:
  podSelector: {}
  policyTypes:
    - Ingress
  ingress:
    - from:
        - podSelector: {}
EOF

    Step 6 — Create the ConfigMap

    oc create configmap cluster-density-config \
  --from-file=config.yml=/tmp/cluster-density-config.yml \
  --from-file=deployment-template.yml=/tmp/deployment-template.yml \
  --from-file=service-template.yml=/tmp/service-template.yml \
  --from-file=route-template.yml=/tmp/route-template.yml \
  --from-file=networkpolicy-template.yml=/tmp/networkpolicy-template.yml \
  -n burner-cluster-density

oc get configmap cluster-density-config -n burner-cluster-density

    Step 7 — Launch the Job

    cat << JOBYAML | oc apply -f -
apiVersion: batch/v1
kind: Job
metadata:
  name: kb-cluster-density
  namespace: burner-cluster-density
spec:
  backoffLimit: 0
  template:
    spec:
      serviceAccountName: kube-burner
      restartPolicy: Never
      initContainers:
        - name: copy-config
          image: quay.io/kube-burner/kube-burner:v2.7.3
          command: [sh, -c, "cp /config-src/* /config/"]
          volumeMounts:
            - {name: config-src, mountPath: /config-src}
            - {name: workdir,    mountPath: /config}
      containers:
        - name: kube-burner
          image: quay.io/kube-burner/kube-burner:v2.7.3
          workingDir: /config
          command: [kube-burner, init, -c, /config/config.yml, --uuid=${UUID}]
          volumeMounts:
            - {name: workdir, mountPath: /config}
      volumes:
        - name: config-src
          configMap:
            name: cluster-density-config
        - name: workdir
          emptyDir: {}
JOBYAML

    Step 8 — Watch the test run

    Wait for the pod to start:

    oc get pod -n burner-cluster-density -w

    Once Running, stream logs:

    oc logs -f job/kb-cluster-density -n burner-cluster-density

    Step 9 — Watch the cluster

    Tab 2 (Home → Projects): Watch the project count climb. Each project = one fully provisioned tenant namespace.

    Tab 3 (Networking → Routes): Filter cluster-density — watch routes appear and show Accepted.

    Tab 4 (Observe → Metrics):

    rate(apiserver_request_total[1m])

    This shows the API server handling the write storm.

    What to say: "Each project you see appearing is a complete application namespace — Deployment, Service, Route, ConfigMaps, Secrets, and NetworkPolicy. This is what one tenant looks like. We're creating 50 of them simultaneously to prove the cluster can run a large SaaS platform."

    Step 10 — Read the results

    INFO podLatency:

    Step 11 — Clean up

    oc delete job kb-cluster-density -n burner-cluster-density 2>/dev/null || true

# Delete all created namespaces
for ns in $(oc get projects --no-headers -o custom-columns=NAME:.metadata.name | grep "^cluster-density"); do
  oc delete project $ns
done

oc delete project burner-cluster-density
oc delete clusterrole kube-burner 2>/dev/null || true
oc delete clusterrolebinding kube-burner 2>/dev/null || true

    Verify clean:

    oc get projects | grep cluster-density
# Should return nothing
